# Lobo DX review after SQLite

The largest repeated costs are resource lifetime bookkeeping, explicit source-bundle configuration and
immutable state reconstruction. The next language change should target a demonstrated pattern. A broader
syntax redesign would add learning cost without evidence of better software construction.

This review implements strict SQL row accessors and corrects current-version guidance. The remaining
recommendations are proposals. Compiler/extension 1.9.0, Core 1.9, native ABI 1 and SQLite extension 1 remain.
[Decision 0056](../decisions/0056-dx-review-and-row-utilities.md) records the selected implementation boundary.
The [result receipt](../benchmarks/results/2026-11-23-dx-review.json) records verification and limitations.

## The library improvement now implemented

The previous `render_row` in the
[SQLite controller](../examples/native/sqlite-rest/controller.lobo) checked list length, took head/tail and
matched both Cell values. Eight rejection arms appeared beside the useful JSON construction.
The SQL library now owns exact shape/class checks through `expect_columns`, `cell_at`, `integer_at`,
`decimal_at`, `text_at` and `bytes_at`. The controller uses:

```lobo
fn row_json(row: Row) -> SqlResult<Json> {
  let checked = try expect_columns(row, 2);
  let id = try integer_at(row, 0);
  let name = try text_at(row, 1);
  Ok(json { "id": integer_text(id), "name": name })
}
```

`render_row` maps the typed result into its existing Valid/Invalid view boundary. Existing IDs and HTTP
behavior remain. No wildcard match, coercion, new native call, new privilege or grammar change is needed.
The ordinary editor resolver already handles these imported functions; a real-bundle regression checks it.

Wrong widths, negative/out-of-range indices, NULL and wrong classes return Decode with backend code zero.
The generic `cell_at` preserves NULL for an explicit nullable policy. Empty text and bytes remain valid.
Access walks the persistent list. These are helpers for the adapter's bounded rows, not random-access arrays.
The tests cover 17 cases in the evaluator and four native modes. An intentionally broken width predicate is
rejected. Four real incompatible database rows produce HTTP 500 responses.

This change centralizes validation. It adds library code and does not remove the underlying Cell distinction.
The controller becomes one line shorter overall; the argument for the helper is reusable validation and a
clear application boundary, not an impressive line-count reduction. New executable sizes are recorded
without claiming an optimization or speedup.

## The first language prototype should be immutable record update

Current code in [transport](../libraries/http-server/transport.lobo) constructs complete ServeState values
when one field changes. The following is proposed syntax and is not accepted by Core 1.9:

```lobo
ServeState { ..state, polls: state.polls + 1 }
```

The bounded rule should require the same nominal record, evaluate the base once, retain all unspecified
fields, evaluate overrides in a defined order and reject repeated or unknown fields. It must preserve
immutability, stable declaration IDs, actions and checked/native behavior. Existing constructors remain.
No inheritance, dynamic object spreading or trait system is needed.

Finish this prototype when HTTP/SQL/tree cases share the rule, invalid cases fail independently, and
compiler, C, LLVM, editor and skill checks agree. Specify fuel and evaluation-order behavior before using
checked equivalence as an oracle. Do not add field shorthand or general destructuring automatically.

## Cleanup needs a separate semantic design

The [SQL wrappers](../libraries/sql/sql.lobo) intentionally retain the outcome before finalization.
The [database owners](../examples/native/sqlite/users.lobo) do the same before close. Replacing the saved
outcome with `try operation()` can skip a close on a handled error. Invocation cleanup already handles native faults and process exit; scoped ownership would make local
teardown predictable across handled returns. A higher-order `with_database` or
`transaction` library callback cannot express an arbitrary actionful body while Fn remains pure.
The compiler probe rejects such a reference with `compile.action.reference`.

A scoped resource design must define successful return, propagated error, body failure plus cleanup failure,
LIFO order, child-before-parent ownership, stale aliases and behavior after fuel/call/heap exhaustion.
It must distinguish language-fault cleanup from running arbitrary user code with exhausted budgets.
Database close must roll back uncommitted work. Transaction commit stays explicit unless a separate
transaction helper specifies exactly what counts as success. Do not add an attractive defer spelling and
leave these outcomes implicit. The existing finite models and counterexample tests should evolve with
any native cleanup change.

## The tooling improvements should share existing facts

The current CLI already emits JSON, source ranges, entries and declared actions. The test runner already
supports pinned sessions, affected verification, explain/replay and an explicit environment identity.
Build on those facilities. A new daemon, language server or MCP wrapper is not required to address the
specific setup and context gaps below.

The [build source list](../scripts/sqlite-rest-sources.json) and
[editor source list](../examples/native/sqlite-rest/SQLiteRest.code-workspace) contain the same eight paths.
A direct check without dependencies fails with `compile.module.invalid`. The editor's project resolver
returns no selected bundle for this file under the repository configuration, so diagnostics fall back to a
single source. Opening the supplied demo workspace works. A shared project description should make that
selection explicit once; it must not introduce ambient imports or automatically activate stored grants.

The [editor resolver](../editors/vscode/src/navigation.cjs) has 1,036 lines and its own native signature
catalog. Rust [native signatures](../src/native_api.rs), C headers and highlighting repeat related facts.
A generated catalog can remove part of that coordination cost. Compiler-owned symbol/type queries can
replace more duplicated resolution later. Keep incomplete-edit behavior and trusted-workspace boundaries.
Independent rejection/ABI tests must not derive all expected results from the same generator they validate.

Nine Rust source files reference Expr variants. Their purposes differ; these counts do not justify a generic
visitor framework or a compiler rewrite by themselves. Extract shared traversal only where semantics and
stage ownership agree. The C providers also share policy concepts across platforms while resource rules
differ. Preserve platform tests and reviewed source/model mappings during any future extraction.

Precise diagnostics should expose expected and actual nominal IDs/types and the failed argument or field.
The current `same` check emits only `types must match exactly`. Explain missing imports, source selection,
try error compatibility and native grants through machine-readable details. Current `check` action summaries
are declared bounds; a future explanation should also identify the call that requires each action.
The test runner's discovery field `source_tokens` should explicitly distinguish per-file 8,192 from aggregate
16,384 tokens. Generic JSON help without tool/build identities also leaves agents to inspect repository files.

Native CLI calls also require stable entry IDs, typed argument atoms and hex-encoded text. Keep the
canonical lossless protocol, but consider typed client helpers or an explicit display mode for common calls.
The foreground test protocol has no launch-grant profile field today; OS/SQLite integration checks therefore
use separate C/Python drivers. A common project/test description should name trusted, pinned profiles and
report unavailable gates explicitly. It must not let a candidate test grant itself arbitrary authority.

A formatter could enforce one modern style through a checked, read-only/dry-run workflow, reusing the
modernization tool's semantic safeguards. It should preserve sidecars and frozen files. Stable IDs already
have authoring commands; deriving IDs anew from names or bodies would lose identity across edits.

## Findings from actual rejected probes

The retained compiler probes show unsupported expression statements, scalar match arms and unparenthesized
complex match subjects. These are current contracts, not regressions. A generic map_error over a user Result
cannot accept a differently owned Native result: `compile.type.mismatch`. Automatic conversion would change
that contract and requires separate evidence. The new row fixture also needed explicit Cell owners inside
List::prepend when expected-type inference did not establish the constructor owner. Keep that documented
fallback; do not introduce a global constructor-name search to make one example shorter.

An initial test fixture had malformed nesting and was replaced by independent named cases. Other corrected
attempts omitted parentheses around a try match subject and passed null instead of absent editor metadata.
The analysis helper's initial missing-module failure is retained separately from its three behavioral checks.
An initial ad hoc project probe had a JavaScript syntax error; the saved corrected probe runs successfully.
The original malformed fixture and original ad hoc syntax-error output were not saved as separate files;
the fixture diagnostic/correction and corrected project probe are retained. These incidental mistakes are
not counted as evidence of a compiler defect or an agent productivity result.

## Stop and measure

This pass ends with the inventory, ranked findings, six SQL helpers, the migrated controller, synchronized
documentation/skill/editor regressions and the recorded checks. It does not add a language construct or
make every recommendation an implementation commitment.

For the next bounded evaluation, freeze equal tasks before changing the language: add a resource owner with
failure cleanup, change one field in a transport state, decode nullable/wrong SQL rows, import a library into
a fresh project, and explain a type/action error. Compare accepted behavior, escaped errors, repair cycles,
comprehension answers, relevant context retrieval and total tokens per accepted change. Include negative and
equal outcomes. Helpers, syntax and diagnostics should be tested as separate treatments where possible.
Source size and static counts are secondary measurements. No new agent trial was run in this review.
