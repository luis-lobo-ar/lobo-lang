## Which backend is better now

The C-to-Clang route is the better current default for this implementation. The final comparison used
six builds and eleven timed native invocations per backend/workload, with fixed independent expected outputs.
Direct LLVM's compile medians were 18.3% to 30.5% higher. Executables were equal in size or eight bytes larger.
Runtime ranges overlap; the comparison establishes no execution-speed improvement or equivalence proof.
The first retained round shows the same pattern. No benchmark observation failed in either round.

Direct LLVM supplies a second native lowering implementation and more direct control over application IR.
Those engineering capabilities are implemented; their future performance/debugging value is unmeasured.
The decision to keep C as default is scoped to current evidence, not a claim that C is universally superior
or LLVM cannot improve. [Decision 0031](../decisions/0031-direct-llvm-native-backend.md) retains the alternatives.

## How to use the LLVM result in the paper

This result belongs in the systems implementation, experimental controls and limitations sections. It helps
separate language constructs and agent feedback from backend execution costs. It does not estimate H1, H2,
H3, code comprehension, token consumption or software-construction effects. No controlled model-agent trial
or comprehension scoring accompanied this backend comparison. Unknown effects remain unknown, not zero.

Suggested wording for a draft, subject to the paper's final analysis:

> With the source language held fixed at Core 0.11, we implemented C/Clang and direct application-LLVM
> lowering with a shared runtime. Two local comparison rounds on four public development programs
> demonstrated no execution-speed improvement from direct LLVM. In the final round, its compile-time
> medians were 18.3% to 30.5% higher, with unchanged or eight-byte-larger executables. These observations
> describe the implemented toolchains on one host and do not measure agent construction or comprehension.

Code comprehension remains a separate required outcome. Future studies need grounded prediction,
dependency, localization and change-impact questions, with source-only and tool-assisted conditions kept
separate. Passing tests and successful compilation do not supply those scores.
