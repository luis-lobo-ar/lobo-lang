# Maintained source modernization — 2026-11-22

Compiler/extension **1.8.1** retain Core **1.8**, checked format 1.0 and native ABI 1. The user asked to
replace maintained code with the available constructs. This is source/tooling maintenance; compiler and
native provider implementation files are byte-identical to the pre-migration snapshot.

## Result

Reviewed 38 maintained library/example/skill sources. Changed 20 source files: 151 compiler-verified token
rewrites and 15 layout cleanups across 19 files, plus independently reviewed try changes in REST setup and
loopback setup/roundtrip. One try file also received automatic changes. The final audit reports zero
remaining accepted rewrites. The source list and artifact hashes are in [the receipt](2026-11-22-modernize-source.json).

The mechanical changes remove 55 constructor-owner qualifiers, seven explicit generic argument lists, two
callback address/specialization spellings and two unused JSON builder imports; replace four Text::concat
calls without reassociation; and simplify 49 expression arms and 32 redundant groups. Each candidate is
compiled in an isolated closed bundle. All resolved checked program fields agree after normalizing only
scope import aliases and duplicate references to the same stable target ID. Layout preserves lexical tokens.

All 38 declaration identity maps agree exactly with the before snapshot. Only the MVC sidecar's unused
json.object/json.field import-alias keys are removed; their target IDs remain dependencies generated by the
JSON literal. The old migration checkpoint still verifies 23 bundles and three embedded sources.

REST setup propagates restrict/listen errors with try. It captures serve's result before closing the listener;
a close error has the same precedence as before. Loopback setup propagates compatible I64 errors across
result owners. Roundtrip still handles the read result before explicit close calls. Native wrappers still
translate I64 into IoError through matches. Transport recovery/retry and cleanup matches remain intentional.
Explicit generic calls and JsonTask qualifiers remain where existing inference has insufficient context.

## Verification and failures

- **274 Rust tests passed**, including checked artifacts, native C/direct LLVM, sanitizers, resource cleanup,
  old checkpoint verification, skill examples and the converged maintained-source audit.
- **166 editor tests passed**, and a real VS Code extension host passed navigation/unsaved diagnostics.
  Host fixtures now navigate inferred constructors/callbacks/calls and reject absent search locations.
- **12 source-tool tests passed**: eight modernizer checks and four historical migration checks.
- Linux before/after binaries each passed 30 pure protocol cases and 35 live TCP scenarios; all recorded
  wire responses and typed failure outputs compare equal. The driver and exact commands are retained.
- The new Windows REST binary passed 35 TCP scenarios with explicit arguments and 35 with default launch
  under Wine. The migrated Windows loopback program passed 16 data/edge/quota cases. Actual Windows 10/11
  execution of these new artifacts is unknown; the earlier user-reported snapshot is a separate program.
- Release build, formatting, Clippy with warnings denied, skill validation, and final JSON/link checks passed.

TDD evidence retains the initial failing codemod stub and failures before the arm/group, layout, builtin
adjacency and match-token-boundary fixes. A full Rust run exposed the retired projection path trying to
resolve contextual Found; that historical test now uses separately frozen pre-migration inputs. Managed
identity tests exposed hardcoded removed imports; they now read tracked metadata. Native comparison tests
exposed alias/duplicate import differences; every other checked field and the resolved ID set remain exact.
The first real editor-host run searched removed explicit generic spellings and failed; corrected fixtures
exercise the inferred forms. A later Rust run caught a negative AST test that no longer removed an arm after
brace simplification; its updated mutation still fails with compile.match.invalid. The first link check found
this report and receipt before they were written; the final check passes. Original failure logs are preserved.

## Preservation and limits

Verified 93 frozen/compiler/provider/model inputs, all 27 prior paper entries and their 64 pinned files, and
all 86 frozen language-1.0 release artifacts. The old migration manifest, version-1 programs, legacy MVC,
illustrative sketches, embedded sessions, upstream provenance and research fixtures remain unchanged.
Dependency locks change only the root package version. See
[decision 0053](../../decisions/0053-maintained-core-1.8-source-modernization.md).

Private raw evidence is retained at `benchmarks/private-evidence/modernize-source-20261122`: before/current
source archives, input hashes, compilers, migration reports, raw failing/passing logs, application driver,
binaries and an integrity manifest. Reports/paper indexes/finalization are excluded from that manifest to
avoid hash cycles. They are indexed separately by the paper evidence register.

The Windows executable is **150,016 bytes**, and its ZIP is **102,317 bytes**. These are artifact facts,
not an attributed optimization result. No runtime speed measurement or agent experiment was run. This work
does not establish token savings, better construction, better comprehension, a larger language contract,
function-scope automatic cleanup or formal correctness of Windows networking. Manual try migration may
change expression-fuel consumption while preserving the tested results at the stated budgets.
